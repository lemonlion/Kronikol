Release {VERSION}: outside a test, TrackingDiagramOverride.StartSetup() and StartAction() set the phase again on xUnit v2 and NUnit, as they did before 4.13.1, and now on MSTest and TUnit too (plans/IDENTITY_OUTSIDE_A_TEST_PLAN.md section 7, the owner's audit of #133's release). A patch: a bug fix, nothing new for a consumer to call. 4.13.1 made the overrides return when no test is running, so that StartAction's marker was no longer logged under an id no scenario owns, but StartSetup only sets the phase and StartAction sets it as well as logging the marker, so the early return dropped the phase too. The phase (TestPhaseContext) is an AsyncLocal every tracker stamps on the calls it logs, and xUnit v2 runs a test on the flow its constructor and IAsyncLifetime.InitializeAsync ran on, so from 4.13.1 to {PREVIOUS} a test class or base class that set the phase there left every call of its tests without one (Unknown). Outside a test both methods now set the phase on their flow, and only StartAction's marker needs a test (a TestIdentityScope's or the global fallback's, else it is dropped). MSTest's and TUnit's overrides threw NullReferenceException outside a test before 4.13.1 and did nothing after it; they now set the phase as the other two do. xUnit v3's override is unchanged (it has set no phase outside a test since 2.31.6, and its constructor and InitializeAsync run inside the test): the plan's Q6. The four overrides' doc comments said they do nothing outside a test, and now say what they do.
