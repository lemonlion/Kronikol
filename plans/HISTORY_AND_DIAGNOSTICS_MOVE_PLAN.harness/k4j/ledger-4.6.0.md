- **History and diagnostics left the default run report (.NET 4.6.0, 2026-10-05).** Not mirrored, a ledger entry only. A default .NET `TestRunReport.html` no longer draws the sparkline, the verdict pill or `data-history-verdicts`, and carries no history or diagnostics CSS and no verdict search code; the History section and the Report diagnostics block were already opt-in (3.21.0). `ShowScenarioHistory`, `ShowHistorySection` and `ShowReportDiagnosticsSection` bring each back, and a new page beside the report, `TestRunReport.labs.html` (no script; scenario names link into the report by `#sid-`), carries all of it by default whenever the run read history or recorded a diagnostic. A default report's `advanced-search.js` and `report-scenario-feature-map-helper.js` are back to the bytes this port ships (the verdict lines are fenced in .NET's sources and stripped), and its stylesheet lost the `.history-*` and `.report-diagnostic*` rules, which moved to two sheets a report carries only when it draws them; the port's stylesheet still differs in other rules. A ledger no longer changes a default .NET report, so for `TestRunReport.html` under default options the cross-run history entry's condition (.NET 3.9.0 to 3.11.0: "byte parity holds whenever there is no ledger") is no longer needed; the other outputs a ledger changes (`History.run.json`, `Failures.md`, the page) still differ. When the port takes cross-run history, the page is what it ports first. Also .NET-only: a merged report that asks for the diagnostics section lists the shards' diagnostics, which `MergeableReportRenderer.Render` dropped.
