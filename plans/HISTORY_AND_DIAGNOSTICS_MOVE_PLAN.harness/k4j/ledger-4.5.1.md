- **Names drawn as text, the component page in standards mode, the CSV export's name columns (.NET 4.5.1, 2026-10-05).** Not mirrored yet, a ledger entry. .NET's run report HTML-encodes feature names, scenario names and the report's title in the feature and scenario headers, the `<title>` and the `<h1>`; it wrote them raw, so a name holding a tag drew the tag, and measured on .NET 4.5.0 a scenario named with an `<img>` and an `onerror` handler ran its script. `ComponentDiagram.html` gains `<!DOCTYPE html>` and a `<title>` (it was drawn in quirks mode) and encodes its heading and its image's `alt`. Kronikol4J's `DotNetHtmlReportRenderer` and `ComponentDiagramReportGenerator` still write the 4.5.0 bytes, so the two ports' pages differ for any name or title holding `&`, `<`, `>`, `"` or `'`, and the component page differs always. The raw names carry the same script risk in the port, so this is worth porting. Export Filtered CSV's Feature and Scenario columns hold the names alone in .NET (a scenario's from its copy button, a feature's from its header's own text); the port's `export_csv` still takes each header's whole text (endpoint, labels, duration badge, button glyphs), the same defect .NET had.
