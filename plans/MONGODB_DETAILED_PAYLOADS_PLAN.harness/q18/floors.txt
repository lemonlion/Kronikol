## What each 3.x driver asks for (its nuspec), and so what a project that takes the driver from Kronikol resolves

- 3.0.0 to 3.8.0: Snappier >= 1.0.0 and SharpCompress >= 0.30.1 (both flagged).
- 3.8.1: Snappier >= 1.3.1, SharpCompress >= 0.30.1 (moderate).
- 3.9.0 to 3.12.0: Snappier >= 1.3.1, SharpCompress >= 0.48.1 (neither flagged). 3.9.0 is the floor.
- Every 2.x from 2.19.0 to 2.30.0 asks for MongoDB.Driver.Core and MongoDB.Bson of its own version; the V2 extension resolves Snappier 1.0.0
  at 2.21.0 and at 2.30.0 alike (NU1903), so its floor does not change that.

## Strong names (AssemblyName of MongoDB.Driver.dll)

- 2.19.0, 2.20.0, 2.21.0, 2.22.0, 2.25.0, 2.26.0, 2.27.0: unsigned (no public key token), assembly version = package version.
- 2.28.0, 2.30.0 and every 3.x tried (3.0.0, 3.9.0, 3.12.0): token 94992a530f44e321, assembly version = package version.
- An unsigned reference does not match a signed assembly at compile time. With the V2 floor at 2.21.0 the V2 suite, on 2.30.0, did not
  compile (CS0012: 'MongoClientSettings' is defined in 'MongoDB.Driver, Version=2.21.0.0, PublicKeyToken=null'); at 2.27.0 it failed with
  376 CS0012 errors (CommandStartedEvent 160, CommandSucceededEvent 88, BsonDocument 66, BsonValue 26, ...). At 2.28.0 it compiles and
  passes. A consumer on a later 2.x whose code hands the extension a MongoClientSettings is in the suite's place, so 2.28.0 is the floor.
