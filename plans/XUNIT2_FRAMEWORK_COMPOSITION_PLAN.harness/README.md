# XUNIT2_FRAMEWORK_COMPOSITION_PLAN harness

Measurements for the plan to let Kronikol.xUnit2 report from a suite that runs on another xUnit v2 test framework
(GitHub #132: Xunit.Extensions.AssemblyFixture's `AssemblyFixtureFramework`), and for the name matching that
`ReportingTestFrameworkExecutor` does today (GitHub #123). Taken on 2026-10-07 against release 4.9.0 (417c8e58).
The measured facts are in [`results/SUMMARY.md`](results/SUMMARY.md), generated from the files beside it.

## What each probe is

All test projects target net8.0 and compile the same test classes from `probe/Shared/` under
`[assembly: TestTracking]`. Every test makes one HTTP call through Kronikol's `TestTrackingMessageHandler`
(`FixedNameForReceivingService = "Svc"`) to an in-process stub, to a path that names the test, and writes
`probe-call: GET <path>` to its output, so the TRX says which call each test made and the report says which
scenario holds it.

| folder | what it is |
|---|---|
| `probe/Shared/` | `Facts` (passes; fails; a failing and a passing `[Fact(DisplayName)]`; `[Fact(Skip)]`), `Theories` (six `[InlineData(row, ms)]` rows that sleep 50/400/100/800/200/20 ms, row 4 fails), `CtorThrows`, `InitThrows` (IAsyncLifetime), `FixtureThrows` (IClassFixture whose constructor throws), `MemberDataNotSerializable` (three rows of a non-serializable object), `DisplayNameDots` (`[Fact(DisplayName = "Order API returns 404 for v1.2")]` and `"Does the thing."`, in a class of their own so whatever they break stays there), and `ProbeHttp` (the tracked client and the stub). The classes are `partial` so E can put them in a collection. |
| `probe/AssemblyFixtureShared/` | `SharedThing`, an `IAssemblyFixture<SharedThing>`, and two test classes that receive it (B and C only). |
| `probe/Prototype/` | The design under test, linked into C, D.Perf and (without `PrototypeFramework.cs`) F: `PrototypeFramework` subclasses `AssemblyFixtureFramework` and wraps the executor `base.CreateExecutor` returns; `Prototype.cs` is the decorator (RunAll/RunTests set `xunit.execution.SynchronousMessageReporting` unless `PROBE_SYNC=0`, and wrap the sink), the sink (a scenario per `ITest` on `ITestStarting`, put in an AsyncLocal; the result matched by `ITest` reference; reports written on `ITestAssemblyFinished` before it is forwarded) and `PrototypeTrackingAttribute`; `ProbeLog.cs` is instrumentation only. |

### How the prototype ties a test's calls to its scenario

The handler attributes a call to whatever `XUnit2TestTrackingContext` holds on the flow, and that is set by
Kronikol's own `TestTrackingAttribute.Before` (a new Guid per test). The harness cannot change that attribute,
so `PrototypeTrackingAttribute` stands in for the real design's change to it: its `Before` reads the scenario the
sink put in the AsyncLocal and copies the id `TestTracking`'s `Before` has just set on the flow onto it
(`XUnit2TestTrackingContext.GetCurrentTestInfo()`, public). No reflection, and nothing internal is touched. It
needs `TestTracking` to run first: both are assembly-level and declared in that order, and the sink records the
order xUnit ran every test's Before attributes in (`IBeforeTestStarting`), so a run where it differed would show.
A test that never reaches Before keeps the scenario's own Guid.

The sink and the executor derive from `Xunit.LongLivedMarshalByRefObject`: xunit.analyzers, which the `xunit`
metapackage brings, fails the build with xUnit3000 for an `ITestFrameworkExecutor` or `IMessageSink` that does
not. A suite writing #132's workaround itself meets the same error.

`PROBE_FORMAT_GUARD=1` makes the sink catch an exception from `FormatScenarioDisplayName` and use the display
name as written; without it the exception leaves `OnMessage(ITestStarting)` as an unguarded design's would.

Lanes (`results/<lane>/<n>/`): `A.OwnFramework` (3 runs), `A.OwnFramework-runner3.1.5` (1), `A2.MethodDisplay` (1),
`A3.StartTimeProbe` (3), `B.AssemblyFixtureOnly` (1), `C.AssemblyFixturePrototype-sync1` and `-sync0` (3 each, formatter
guarded), `C.AssemblyFixturePrototype-sync1-unguarded` and `-sync0-unguarded` (3 each), `E.CollectionFixtureOnly` (3),
`F.DependencyInjectionPrototype-sync1` and `-sync0` (3 each, formatter guarded); `G.FormatterProbe` runs once; `perf/` is
perf.ps1's.

## How to run

Needs PowerShell 7, Python 3, the .NET 8 runtime, the SDK the repository's `global.json` selects (10.0.x) and
nuget.org.

```powershell
pwsh plans/XUNIT2_FRAMEWORK_COMPOSITION_PLAN.harness/run.ps1                 # every lane; the repeated ones 3 times
pwsh plans/XUNIT2_FRAMEWORK_COMPOSITION_PLAN.harness/run.ps1 -Lanes "A.OwnFramework,E.CollectionFixtureOnly" -Runs 1
pwsh plans/XUNIT2_FRAMEWORK_COMPOSITION_PLAN.harness/run.ps1 -CompareOnly    # re-compare saved runs, rewrite SUMMARY.md
pwsh plans/XUNIT2_FRAMEWORK_COMPOSITION_PLAN.harness/perf.ps1                # 5 rounds of C sync on, C sync off, A
```

Both scripts build with `--artifacts-path .build/main` (`.build/runner3` for A on runner 3.1.5), so the src projects they reference build into the
harness (`.build/` is ignored by the harness's `.gitignore`) and nothing is written under `src/`. A plain
`dotnet build` of a probe writes `bin/` and `obj/` under `src/Kronikol` and `src/Kronikol.xUnit2` instead.

Both set `KRONIKOL_HISTORY=off`. Without it a run finds the repository above its output and appends its line to
the working tree's `.kronikol/history.jsonl`: the first trial run did that, and the file was removed.

Environment variables the probes read: `PROBE_SYNC` (`0` leaves the runner's message reporting alone),
`PROBE_FORMAT_GUARD` (`1` guards the formatter), `PROBE_LOG` (path of the prototype's event log; `run.ps1` sets
it for C and F), `PROBE_TIMING` (file the prototype appends its assembly time and report time to; `perf.ps1` sets it),
`PROBE_REPORTS` (the prototype's reports directory; default `<test output>/Reports`).

Never open a `TestRunReport.json` or `.html`: `tools/compare.py` reads the JSON field by field, and
`tools/keys.py` prints its key tree without values.

.NET 8.0.27; SDK 10.0.300; Windows 11. `Directory.Build.props` here stops MSBuild's upward search, so the
repository root's `Directory.Build.props` (Version 4.9.0, LangVersion preview, documentation and pack items) does
not apply to the probes; the repository has no `Directory.Packages.props` or `Directory.Build.targets`.

## Result files

`results/<lane>/<n>/` for each run:

| file | holds |
|---|---|
| `console.txt` | `dotnet test` output, console logger at normal verbosity |
| `run.trx` | the TRX (`--logger "trx;LogFileName=run.trx"`) |
| `compare.txt`, `compare.json` | `tools/compare.py`: per xUnit test, the scenario holding its call (or with its names), result, duration, error first line and calls, with flags; tests with no scenario; scenarios with no test; scenario results; the report's start and end against the TRX's; the background section's paths |
| `report-extract.json` | the fields of TestRunReport.json that compare.py reads, plus how often each test's path occurs anywhere in the file (`run.ps1 -CompareOnly` compares from it) |
| `Failures.md`, `Run.json` | copied from the report directory, when written |
| `reports-files.txt` | the report directory's files and sizes, or that there was none |
| `run-info.json` | lane, environment variables, exit code, wall time |
| `*.log.txt` | `prototype-formatter.log`, `prototype-error.log` or `kronikol-error.log` from the test output, when written (renamed: the repository's `.gitignore` drops `*.log`) |
| `starttime-probe.txt` | A3 only: `ReportLifecycle.StartTime` read after the run, with when the test assembly's code was first used and when the process exited |
| `asynclocal.tsv`, `asynclocal.scenarios.tsv` | C and F only: the prototype's event log (ITestStarting, Before, test body, result; thread, microseconds, whether the AsyncLocal held the test's scenario) and one row per ITest (result, Before attributes in order, ids) |
| `asynclocal.txt`, `asynclocal.json` | C and F only: `tools/asynclocal.py`'s per-test visibility table and counts |

`results/B.AssemblyFixtureOnly/both-attributes-build.txt`: the build errors with both TestFramework attributes.
`results/G.FormatterProbe/output.txt`: the formatter's output or exception per input.
`results/perf/perf.tsv`: one row per perf run (columns explained in `tools/perf_row.py`).
`results/SUMMARY.md`: everything above, as measured facts with the file each came from (`tools/summarize.py`).
