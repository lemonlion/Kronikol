47a0203b Release 4.10.0: MongoDB tracking takes an IHttpContextAccessor through its options (#136; plans/MONGODB_ACCESSOR_OPTION_PLAN.md R1, roadmap row 1.22). A minor: MongoDbTrackingOptions.HttpContextAccessor is new public surface, in Kronikol.Extensions.MongoDB and Kronikol.Extensions.MongoDB.V2 (one source), and code that does not set it behaves as before. MongoClientSettings.WithTestTracking built its subscriber with no accessor, so the commands a host ran while it served a request were lost unless the host registered AddTestTrackingContextPropagation(), and went to a test id no scenario has when the fetcher answered one outside a test (#133). The plan measured both on 4.9.0, in TestServer hosts with MongoDB.Driver 2.30.0 and 3.12.0 against MongoDB 7.0. The subscriber now falls back to the options' accessor when its constructor is given none, so WithTestTracking carries it, and AddMongoDbTestTracking passes the options' accessor before the container's. The eight MongoDbTrackingOptions members that had no XML doc have one. AddMongoDbTestTracking's says that the subscriber it registers records nothing until a client subscribes it, and CurrentStepTypeFetcher's that the subscriber does not read it (no extension reads its own: plan section 8). Tests: a host lane, MongoDbHostAttributionTests, runs a TestServer host on a real MongoDB (the server KRONIKOL_TEST_MONGO names, or Testcontainers.MongoDb 4.8.1) in both MongoDB test projects. WithTestTracking_PreservesExistingClusterConfigurator asserted only that the configurator was replaced, and now runs it. The MongoDB classes that read or clear the process-wide TrackingComponentRegistry share one collection. Proofs (plan harness r1/): with the property added and nothing reading it, the four behaviour facts failed for their own reasons, the host lane reading right 0, wrong 8 (red-property-only-v3-detail.txt); six mutations were each caught by exactly the facts the plan names (mutations.txt); and the probe on local 4.10.0 packages reads right 8 through RequestHeader in all six cells of row N on both drivers, with rows A, D, W and X as on 4.9.0 (results/probe-r1-local*.txt). Both MongoDB test projects pass 177, TcpTap 265 with 4 skipped, the core suite 6,903 with 2 skipped, and release.slnf builds and packs in Release for every target (62 packages). The templates pin 4.9.1 and the history action's VERSION installs Kronikol.Tool 4.10.0. The wiki edits follow publication. The report output does not change, so Kronikol4J's ledger gets no line
